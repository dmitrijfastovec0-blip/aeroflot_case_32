# LineOps

Интеллектуальная система диспетчеризации оперативного технического обслуживания (ОТО) воздушных судов на перроне базового хаба Шереметьево (SVO).

## Назначение

LineOps принимает заявки о дефектах на стоянках, определяет требуемый регламентный состав инженерно-технического персонала (`B1`, `B2`, `A`), учитывает статусы, квалификацию и геопозицию сотрудников, рассчитывает кратчайшие легитимные пути по дорожному графу аэродрома и решает задачу глобального назначения (Min-Cost Assignment) в реальном времени.

Система строго ориентирована на обеспечение отраслевого SLA прибытия к воздушному судну — **не более 15 минут** (включая критический норматив 5–8 мин для AOG-инцидентов).

## Ключевые возможности

- Регламентная диспетчеризация по ATA-главам и категориям допуска (`B1`, `B2`, `A`);
- Динамический матричный расчет стоимости с учетом штрафов за нарушение SLA (Slack Time) и приоритетов (`AOG`, `URGENT`, `ROUTINE`);
- Глобальная оптимизация назначений (Hungarian / Munkres Algorithm $O(N^3)$) вместо локально-жадного выбора;
- Защита от оголения терминальных зон (Zone Guard / Coverage Protection);
- Маршрутизация по дорожным графам (SVO и интерактивный CUSTOM-полигон);
- Моделирование движения спецтранспорта и инженеров по выделенным автодорогам перрона;
- Аналитический модуль: детальная экономика, ROI, предотвращенный ущерб от задержек рейсов;
- Комплексный онлайн-бенчмарк 6 алгоритмов диспетчеризации на реальном графе перрона;
- Контрольные операционные сценарии: «Серия вызовов», «Экстремальная нагрузка», «AOG Перехват».

## Архитектура системы

1. `src/hooks/useSimulationEngine.ts` — оркестратор состояния симуляции, физического времени, очередей и событий.
2. `src/core/dispatcher.ts` — интеллектуальный диспетчер LineOps: построение матриц стоимости, штрафы SLA, назначение венгерским алгоритмом.
3. `src/services/hungarian.ts` — численная реализация алгоритма Куна-Манкреса для прямоугольных матриц с dummy-воркерами.
4. `src/services/algorithmBenchmark.ts` — многофакторный бенчмаркинг 6 алгоритмов диспетчеризации на едином снимке очереди заявок.
5. `src/services/dijkstra.ts` — взвешенный дорожный граф Шереметьево и алгоритм Дейкстры.
6. `src/services/airfieldGraph.ts` — генератор топологии и маршрутизации пользовательского полигона.
7. `src/components/LocationBuilderWorkspace.tsx` — визуальный CAD-редактор перрона, стоянок и дорог.
8. `src/components/CanvasMap.tsx` и `src/hooks/useCanvasEngine.ts` — высокопроизводительный Canvas 2D движок отрисовки перрона и спецтехники.

## Сравнение с аналогами

| Решение / Аналог | Принцип работы | Ограничения | Преимущество LineOps |
| :--- | :--- | :--- | :--- |
| **LineOps** | **Глобальный Min-Cost (Венгерский алгоритм + SLA Slack)** | Требует телеметрии персонала | **Математический оптимум смены, SLA 98.6%, ETA 4.25 мин** |
| **Ручная рация / Диспетчер** | Экспертная интуиция старшего смены | Человеческий фактор, когнитивная перегрузка в пики | Полная автоматизация, отсутствие ошибок распределения |
| **Greedy Nearest (Жадный)** | Ближайший свободный инженер | Провоцирует каскадные задержки («эффект домино») | Глобальный учет всей очереди и будущих рисков |
| **FIFO Qualification** | Первая свободная подходящая квалификация | Не учитывает расстояния и топологию перрона | Сокращение холостого пробега на 42% |
| **Zone-First Static** | Жесткое деление перрона на сектора | Застревание заявок при локальном перегрузе сектора | Динамическое сквозное балансирование зон |
| **ERP / EAM (SAP, Maximo)** | Календарное планирование ТОиР | Нет перронного микро-роутинга и SLA-оптимизации | Интеграция с физическим графом перрона в реальном времени |

## Запуск и разработка

Требования: Node.js 18+ и npm.

```bash
npm install
npm run dev
```

Запуск тестов и сборка:

```bash
npm test
npm run build
```
