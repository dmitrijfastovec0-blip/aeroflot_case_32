# Воздухан

Интерактивный прототип умной диспетчеризации оперативного технического обслуживания воздушных судов на перроне.

## Назначение

Система принимает заявку о дефекте на стоянке, определяет требуемую квалификацию, учитывает свободных и занятых сотрудников, рассчитывает маршрут по дорожному графу и показывает движение бригады на карте.

Прототип ориентирован на норматив прибытия к воздушному судну не более 15 минут.

## Возможности

- квалификации `B1`, `B2` и `A`;
- типы дефектов ATA и регламентный состав бригады;
- приоритеты `AOG`, `URGENT`, `ROUTINE`;
- учёт текущего статуса, загрузки и местоположения сотрудников;
- расчёт ETA и маршрута по графу дорог;
- маршрутизация по SVO и пользовательскому CUSTOM-полигону;
- визуализация стоянок, баз, сотрудников, спецавтомобилей и маршрутов;
- автоматическое и ручное назначение;
- возврат на базу и локальное патрулирование;
- стресс-тест по всем стоянкам;
- контрольные сценарии и сравнение с прямолинейным выбором ближайшего сотрудника;
- расчёт наблюдаемого сокращения времени ожидания.
- воспроизводимый benchmark алгоритмов на одном snapshot очереди и сотрудников.

## Архитектура

1. `src/hooks/useSimulationEngine.ts` управляет состоянием симуляции, временем, сценариями и переходами сотрудников.
2. `src/core/dispatcher.ts` строит очередь, учитывает приоритеты, квалификацию, занятость и выполняет глобальное назначение.
3. `src/services/dijkstra.ts` содержит граф и маршрутизацию SVO.
4. `src/services/airfieldGraph.ts` строит граф пользовательского полигона и выполняет Dijkstra по явно нарисованным дорогам.
5. `src/components/LocationBuilderWorkspace.tsx` позволяет создавать стоянки, базы, узлы и дороги.
6. `src/components/CanvasMap.tsx` и `src/hooks/useCanvasEngine.ts` визуализируют карту и движение.

## Аналоги

| Аналог | Сильная сторона | Ограничение относительно задачи ОТО |
| --- | --- | --- |
| Ручная диспетчеризация | Гибкость и отсутствие внедрения | Человеческий фактор, нет воспроизводимого расчёта |
| Ближайший свободный инженер | Быстрый локальный выбор | Не оптимизирует очередь и дорожный граф глобально |
| ERP/EAM для ТОиР | Заявки, история и регламентные работы | Требуется отдельная оперативная карта перрона |
| Airport Operations Management | Общий операционный контекст аэропорта | Интеграция для узкой задачи ОТО может быть избыточной |
| Воздухан | Квалификация, загрузка, ETA, SLA и граф маршрутов в одном прототипе | Координаты симулируются; промышленная интеграция не реализована |

Источники для дальнейшей проверки аналогов:

- IATA Ground Operations: https://www.iata.org/en/programs/ops-infra/ground-operations/
- SAP Asset Management: https://www.sap.com/products/erp/asset-management.html
- IBM Maximo: https://www.ibm.com/products/maximo
- SITA Airport Operations: https://www.sita.aero/solutions/

## Экономический эффект

Для каждой записи диспетчеризации система сохраняет ETA системы и ETA baseline на одной и той же заявке. Все показатели в аналитике считаются по одному массиву `DispatchStat`, поэтому алгоритмы не сравниваются на разных выборках.

После завершения задач система сравнивает фактическое ETA выбранного алгоритма с прямолинейным baseline:

```text
сэкономленные минуты = сумма(ETA_baseline - ETA_системы)
предотвращённый ущерб = сэкономленные минуты × стоимость минуты простоя
```

Текущая демонстрационная ставка хранится в `src/constants/index.ts` как `AIRCRAFT_DOWNTIME_COST_PER_MIN`. Пока официальный источник ставки не приложен, значение является демонстрационным допущением и не должно выдаваться за утверждённый норматив.

## Контрольные сценарии

Сценарии доступны через меню «Сценарии»:

- базовый день;
- серия вызовов;
- пиковая нагрузка;
- стресс-тест по всем стоянкам;
- AOG-перехват;
- кадровый дефицит;
- снегопад и изменение скоростей;
- сброс смены.

Функция `runControlTests` дополнительно проверяет квалификацию, выбор минимального ETA, массовую очередь и скорость большого числа расчётов. В CUSTOM-режиме тесты используют CUSTOM-граф, а не SVO-граф.

В окне аналитики доступны кнопки «Запустить тесты» и «Запустить benchmark». Benchmark выполняет четыре алгоритма на одной очереди: `Воздухан`, `Greedy nearest`, `FIFO qualification` и `Zone-first`. Показываются размер выборки, число назначений, средний ETA, P95 и SLA.

## Запуск

Требования: Node.js 18+ и npm.

```bash
npm install
npm run dev
```

Проверка проекта:

```bash
npm test
npm run build
```

## CUSTOM-полигон

1. Откройте «Конструктор испытательного полигона».
2. Разместите стоянки и операционные базы.
3. Соедините их инструментом «Автодорога».
4. Запустите симуляцию.
5. Проверьте стресс-тест и контрольные сценарии.

Патрули используют только связи `ROAD`. Назначение на стоянку без достижимого маршрута блокируется, а не превращается в прямой переход.

## Использование ИИ при разработке

ИИ применялся как вспомогательный инструмент для поиска дефектов, подготовки вариантов реализации и проверки граничных случаев. Архитектура, ограничения, интеграция изменений, тесты и финальная проверка выполнялись и принимались разработчиком вручную. Неподтверждённые числовые показатели не используются как результаты измерений.

## Ограничения прототипа

- координаты сотрудников и воздушных судов симулируются;
- нет подключения к GPS, трекерам, системам ТОиР или расписанию вылетов;
- экономическая ставка требует подтверждения организации;
- видео и презентационные материалы готовятся отдельно.
